# Beauty Clinic — Django версія
Система управління салоном краси на Django.

## Installation
```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
cd myproject
python manage.py runserver
```

## Features
- Головна сторінка
- Список клієнтів
- Деталі клієнта з замовленнями
- Список послуг
- Деталі послуги

- Інвентар

## Сторінки

### Головна сторінка (/)
Показує заголовок "Головна сторінка" та опис системи управління салоном краси.

### Клієнти (/clients/)
Показує заголовок "Клієнти" та таблицю клієнтів.

### *Деталі клієнта* (/clients/id/)
Показує деталі окремого клієнта і деталі його замовлення.

### Послуги (/services/)
Показує заголовок "Послуги" та таблицю послуг.

### *Деталі послуги* (/services/id/)
Показує назву послуги і деталі окремої послуги.

### Замовлення (/orders/)
Показує заголовок "Замовлення" та таблицю замовлень.

### *Деталі замовлення* (/orders/id/)
Показує деталі окремого замовлення.

### Інвентар (/inventory/)
Показує список матеріалів на складі.

### Графік (/schedule/)
Показує графік запису клієнтів.

### Дашборд (/dashboard/)
Показує статистику проєкту.

### Про проєкт (/about/)
Показує заголовок "Про проєкт" та інформацію про Django реалізацію Beauty Clinic.

## REST API
REST API доступен за адресою: http://127.0.0.1:8000/api/

### API endpoints
 
#### Клієнти
- GET /api/clients/ — список клієнтів (авторизовані)
- POST /api/clients/ — створення клієнта (персонал)
- GET /api/clients/{id}/ — деталі клієнта
- PUT /api/clients/{id}/ — повне оновлення (персонал)
- PATCH /api/clients/{id}/ — часткове оновлення (персонал)
- DELETE /api/clients/{id}/ — видалення (персонал)
 
#### Послуги
- GET /api/services/ — список послуг (авторизовані)
- POST /api/services/ — створення послуги (персонал)
- GET /api/services/{id}/ — деталі послуги
- PUT /api/services/{id}/ — повне оновлення (персонал)
- PATCH /api/services/{id}/ — часткове оновлення (персонал)
- DELETE /api/services/{id}/ — видалення (персонал)
 
#### Замовлення
- GET /api/orders/ — список замовлень (авторизовані)
- POST /api/orders/ — створення замовлення (авторизовані)
- GET /api/orders/{id}/ — деталі замовлення
- PUT /api/orders/{id}/ — повне оновлення (автор або адмін)
- PATCH /api/orders/{id}/ — часткове оновлення (автор або адмін)
- DELETE /api/orders/{id}/ — видалення (автор або адмін)
- GET /api/orders/?status=completed — фільтрація за статусом
- POST /api/orders/{id}/complete/ — завершити замовлення/власний endpoint (автор або адмін)
 
#### Інвентар
- GET /api/inventory/ — список інвентарю (авторизовані)
- POST /api/inventory/ — створення запису (персонал)
- GET /api/inventory/{id}/ — деталі
- PUT /api/inventory/{id}/ — повне оновлення (персонал)
- PATCH /api/inventory/{id}/ — часткове оновлення (персонал)
- DELETE /api/inventory/{id}/ — видалення (персонал)
 
#### Статистика
- GET /api/statistics/ — статистика проєкту

### Документація API
Swagger UI доступний за адресою: http://127.0.0.1:8000/api/docs/

### Приклади запитів


## REST API автентифікація

### Отримання токена
Для доступу до API необхідно отримати токен:
POST /api/token/
{
"username": "admin",
"password": "admin123"
}

 
Відповідь:
```json
{
    "token": "ваш_токен"
}
```

### Використання токена
Додайте заголовок до запитів:

Authorization: Token ваш_токен

### Дозволи
GET запити — авторизовані користувачі
POST/PUT/PATCH/DELETE — авторизовані користувачі
Створення клієнтів/послуг/інвентарю — тільки персонал (is_staff)
Редагування замовлень — тільки автор або адмін

### Тестування
Запуст тести:
```bash
cd myproject
pytest tests/test_api_auth.py -v
```

## Автентифікація

### Реєстрація (/register/)
Можна зареєструвати нового користувача. Для реєстрації потрібно ввести:
- Логін (username)
- Пароль
- Підтвердження пароля

Після успішної реєстрації користувач автоматично входить в систему.

### Вхід в систему (/login/)
Для тестування використовуйте:

**Адміністратор (доступ до адмін-панелі)**
- Username: admin
- Password: admin / встановлено при створенні суперкористувача

**Менеджер (повний доступ через адмінку)**
- Username: manager
- Password: managerpassword / створено через Django Admin для перевірки дозволів

**Редактор (обмежений доступ через адмінку)**
- Username: editor
- Password: editorpassword / створено через Django Admin для перевірки дозволів

** Тестові дані для превірки, не для використання в реальному проєкті.

### Захищені сторінки
- `/profile/` — профіль користувача (тільки авторизовані)
- `/my-orders/` — мої замовлення (тільки авторизовані)

### Захист функціоналу
- Створення замовлень доступно тільки авторизованим користувачам
- Редагування замовлень доступно тільки автору або суперкористувачу
